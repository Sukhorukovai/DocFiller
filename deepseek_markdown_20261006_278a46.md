## Назначение

Автоматическое заполнение шаблонов Word (договоры, акты) реквизитами
контрагентов. Источники реквизитов: `.doc` / `.docx` / `.pdf` / `.jpg`
/ `.png` / `.tif` — через Word bridge + Tesseract OCR.

## Что работает

### Парсер реквизитов
- `python debug_requisites.py > report.txt 2>&1` → 22/26 [OK], 4 «проблемных»
  файла — это на самом деле корректные случаи (шаблоны без реквизитов,
  карточки без банковских полей и т. п.).
- Карточки, сканы `.jpg`, PDF — все обрабатываются.

### Парсер договоров (`parse_filled_contract`)
Извлекает Заказчика из всех 6 образцов. Ключевые решения:
1. HEAD — фрагмент перед «именуемое в дальнейшем «Заказчик»»,
   обрезанный по последнему «с одной стороны».
2. BLOCK — блок после ПОСЛЕДНЕГО «Заказчик:».
3. Для ИП — только BLOCK (в tail лежит блок «Подрядчик:»).
4. Для юрлиц — BLOCK (без tail, иначе утекают чужие банковские реквизиты).
5. ИНН с пробелами — отдельный regex.
6. Родительный падеж ФИО → именительный.
7. Короткое ФИО «Романенко В.В.» распознаётся.
8. Из `_NAME_STOPWORDS` убран «ЗАВОД».

### ActProcessor
- Дата акта → текущая, красным, первая строка жирным.
- Плейсхолдер `|_____|` → полное описание Заказчика (красным).
- Маркер **CONTRACT** (латиницей, капсом, без скобок) → «по Договору № X от Y»
  (красным). Если `contract_no` пусто — маркер удаляется.
- Маркеры `{16 000,00}` в таблице → актуальная сумма (по центру, красным).
- «Общая стоимость работ …» переписана целиком (красным).
- Колонка «Заказчик» → реквизиты, красным, интервал 1.2.
- Дедупликация р/с, к/с, ИНН, КПП, БИК.
- XML-обход (`doc.element.body.iter(qn('w:p'))`) — находит маркер даже
  в `w:sdt` / `w:smartTag` / таблицах.

### GUI
- Поля «Договор - Акт», «Реквизиты».
- Панель «Папки по умолчанию» (Входящие / Исходящие) — сохраняется в
  `config.json`.
- Кнопки: `[Договор - Акт]` `[Реквизиты]` … `[Результат]` `[Сформировать]`.
- Авто-определение типа реквизитов (contract / act / card).
- Для акта из договора — №/дата/сумма автоматически.
- Для акта из карточки — диалог ввода суммы.
- Готовый файл сохраняется в Исходящие (или рядом с шаблоном, если
  папка не задана).

## Постпроцессинг — порядок вызовов

Каждый шаг вызывается из `_process` в `gui/app.py`.
Функции живут в `gui/app.py`, у каждой маркер `# [...]` в коде.

| # | Функция | Что делает |
|---|---|---|
| 1 | `_remove_contract_empty_paragraph` | удаляет пустую строку от CONTRACT (python-docx, по шапке главной таблицы) |
| 2 | `_apply_requisites_spacing` | межстрочный 1.2 в колонке «Заказчик» |
| 3 | `_remove_leading_blank_paragraph` | ведущие пустые абзацы (Word COM) |
| 4 | `_strip_empty_headers` | удаляет ВСЕ колонтитулы: `header*.xml`, `footer*.xml`, ссылки в document.xml, `titlePg`, записи в `[Content_Types].xml` и `document.xml.rels` |
| 5 | `_sync_page_margins` | копирует `w:pgMar` из шаблона (.docx — zipfile, .doc — Word COM) |
| 6 | `_clamp_header_margins` | гарантирует `header ≤ top−200`, `footer ≤ bottom−200` |
| 7 | `_ensure_sane_margins` | если в результате `pgMar` содержит мусор (`>5000 twips`) — заменяет на A4 |
| 8 | `_fix_initials_in_docx` | `«В.в.» → «В.В.»` во всех `w:t` |

**Итоговые A4-поля, которые должен иметь результат:**
```
<w:pgMar w:top="567" w:right="850" w:bottom="1134"
         w:left="1418" w:header="284" w:footer="708" w:gutter="0"/>
```
(1 см сверху и 1 см снизу, 1.5 см слева, 1.5 см справа.)

## Важные уроки (грабли)

### 1. Word COM возвращает 9999999
`Documents.Open` **без** `Repaginate()` иногда отдаёт `PageSetup.TopMargin
= 9999999` — служебное «не инициализировано». Умножение на 20 (твипы)
даёт `199999980`. Если это значение попало в `pgMar`, документ обжимается
в полоску: **одна буква в строке**, Word показывает «Режим ограниченной
функциональности».

**Защита:** `_is_bad_pgmar(tag)` — если любое поле > 5000 твипов,
значение считается мусором и **не применяется** (см. `_ensure_sane_margins`,
`_sync_page_margins`).

### 2. Причина «ломает только договоры»
Шаблоны договоров — `.doc` (Образец1.doc … Образец6.doc).
Шаблон акта — `.docx` (`Акт.docx`).
Для `.doc` `_sync_page_margins` идёт через Word COM (отсюда мусор).
Для `.docx` — через zipfile, безопасно.

### 3. `pStyle="a5"` в шаблоне содержит `spacing before`
Если просто **снять** стиль с первого абзаца — уйдёт оформление
(центрирование, жирность, размер). Правильно — **не снимать стиль**,
а менять только `pgMar` и уменьшать `top`, чтобы компенсировать `before`.

### 4. `header > top` = текст «отжимается» вниз
Word резервирует под колонтитул столько, сколько в `header`. Если
`header > top` — верхний текст съезжает на `header`. Отсюда
`_clamp_header_margins`.

### 5. `__slots__` у `Requisites`
`vars(req)` бросает `TypeError`. Нормализацию полей нужно делать
**на уровне `dict` внутри `parse_requisites`**, а не через `vars(req)`.

### 6. PowerShell портит многострочные here-string
`@'...'@ | Set-Content` иногда обрезается или ломает кодировку
(`Add-Content` пишет в cp1251, Python 3.13 читает как UTF-8).
**Скрипты длиннее 5 строк — сохранять через Блокнот** (тип «Все файлы»,
UTF-8).

### 7. `dump_style.py` / `fix_style.py` — для ремонта старых файлов
`fix_style.py "путь.docx" [top_twips]` — создаёт `<имя>.repaired.docx`
с A4-полями. Только для файлов, сломанных **до** установки `_ensure_sane_margins`.
Новые генерации в ремонте не нуждаются.

### 8. Значок `¶` в углу
Если в Word виден `¶` слева сверху — это **не абзац**, а область
колонтитула. Кликните в тело документа — исчезнет. Если остаётся —
значит в `settings.xml` флаг `evenAndOddHeaders` или в `document.xml`
ссылки на header/footer. Лечится `_strip_empty_headers`.
